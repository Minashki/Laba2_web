# Python Web Security Lab

## 1. Описание проекта

Данный проект разработан в рамках лабораторной работы № 2 по Python и посвящён изучению уязвимостей веб-приложений.

В проекте создано локальное веб-приложение на Python с использованием стандартных библиотек. Оно демонстрирует две распространённые уязвимости веб-безопасности: SQL Injection и Path Traversal.

Для каждой уязвимости подготовлены тестовый скрипт, позволяющий проверить её наличие, и исправленная версия приложения, демонстрирующая способы защиты.

## 2. Используемые технологии

В проекте используются стандартные библиотеки Python:

- `http.server` — создание локального HTTP-сервера и обработка HTTP-запросов.
- `urllib.parse` — разбор URL и получение параметров запросов.
- `sqlite3` — работа с базой данных SQLite.
- `pathlib` — работа с путями к файлам и проверка расположения файлов.

Дополнительные сторонние библиотеки и веб-фреймворки не используются.

## 3. Реализованные уязвимости

### 3.1. SQL Injection

SQL Injection — уязвимость, при которой пользовательский ввод может изменить структуру SQL-запроса.

В уязвимой версии имя пользователя напрямую подставляется в SQL-запрос. Из-за этого специально сформированный ввод может изменить условие поиска и привести к выводу всех пользователей из базы данных.

**Исправление:** в `app_fixed.py` используется параметризованный SQL-запрос с плейсхолдером `?`. Значение пользователя передаётся отдельно от SQL-команды, поэтому ввод не интерпретируется как часть SQL-синтаксиса.

### 3.2. Path Traversal

Path Traversal — уязвимость, при которой некорректная проверка имени файла позволяет обратиться к файлам за пределами разрешённого каталога.

В уязвимой версии имя файла используется при формировании пути без проверки, что позволяет через последовательности вроде `../` обратиться к файлу за пределами папки `public`.

**Исправление:** в `app_fixed.py` путь нормализуется с помощью `pathlib.Path.resolve()`, после чего проверяется, находится ли файл внутри разрешённого каталога `public`. Если путь выходит за пределы каталога, доступ запрещается.

## 4. Структура проекта

- `app_vulnerable.py` — версия приложения с намеренно оставленными уязвимостями.
- `app_fixed.py` — исправленная версия приложения.
- `test_sql_injection.py` — тест для демонстрации SQL Injection.
- `test_path_traversal.py` — тест для демонстрации Path Traversal.
- `fixes.patch` — файл с изменениями между уязвимой и исправленной версиями.
- `public/info.txt` — пример публичного файла.
- `secret.txt` — учебный файл за пределами публичного каталога.
- `README.md` — описание проекта и инструкция по запуску.
- `.gitignore` — список файлов, которые не следует добавлять в репозиторий.

База данных `users.db` создаётся приложением при запуске и не должна добавляться в репозиторий.

## 5. Запуск приложения

Для запуска требуется установленный Python 3.

Перейдите в каталог проекта:

```bash
cd ~/lab2
```

### Запуск уязвимой версии

```bash
python3 app_vulnerable.py
```

После запуска приложение доступно по адресу:

http://127.0.0.1:8000

### Запуск исправленной версии

Сначала остановите работающий сервер сочетанием `Ctrl+C`, затем выполните:

```bash
python3 app_fixed.py
```

Для каждой версии используется один и тот же локальный адрес. Одновременно запускать обе версии на порту `8000` не нужно.

## 6. Запуск тестов

Сервер должен быть запущен в отдельном терминале. Тесты выполняются из каталога проекта в другом терминале.

### Проверка SQL Injection

```bash
python3 test_sql_injection.py
```

На уязвимой версии тест должен подтвердить возможность получить всех пользователей с помощью специально сформированного запроса. На исправленной версии инъекция не должна приводить к выводу всех пользователей.

### Проверка Path Traversal

```bash
python3 test_path_traversal.py
```

На уязвимой версии тест должен показать возможность прочитать учебный файл за пределами каталога `public`. На исправленной версии попытка должна блокироваться.

## 7. Результаты работы

В ходе выполнения лабораторной работы были реализованы и изучены две уязвимости веб-приложений. Для каждой уязвимости проведена проверка на локальном сервере и подготовлен пример исправления.

Работа позволила изучить обработку HTTP-запросов в Python, работу с базой данных SQLite, использование параметризованных SQL-запросов и безопасную проверку путей к файлам.
